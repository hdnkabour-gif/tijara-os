> قاعدة الاختبار: PostgreSQL 16.15 محلي، تُعاد بناؤها نظيفة عند كل تشغيل، والتطبيق يتصل بدور `app_runtime`.

## كيف تُشغَّل
```bash
./scripts/setup-db.sh                 # مرة واحدة (أدوار وقاعدة اختبار محلية)
npm install --include=dev             # ملاحظة: NODE_ENV=production في هذه البيئة يتجاهل devDependencies
npm run typecheck && npm test
```

## ما اكتشفته أثناء البناء (وأصلحته)
- خطأ نوع `uuid = text` في استعلامات الدفعات الفارغة؛ كشفه اختبار الحجز المتزامن. أُصلح بـ `::uuid`.
- سلوك البيئة: `NODE_ENV=production` يمنع تثبيت devDependencies بصمت.
- **تعديل على الوثيقة:** «خدمة تستهلك مواد» (فحم/توابل) تُمثَّل `kind=composite` + `fulfillment=backflush` وليس `kind=service`، لأن قيد القاعدة يلزم الخدمة الصرفة بـ `fulfillment=none`.

## فحوص النشر (محلياً، ليست على Railway)
محاكاة مزوّد: قاعدة جديدة بمستخدم superuser، ثم `migrate` ثم الخادم بوضع الإنتاج. نتائج فعلية:
- الترحيل يُطبَّق مرة واحدة، والتشغيل الثاني لا يفعل شيئاً. كلمة مرور أقل من 16 حرفاً مرفوضة.
- الإقلاع بوضع الإنتاج بلا كلمات مرور الأدوار يفشل (لا تُستعمل كلمات التطوير أبداً في الإنتاج).
- `/ready` يعطي 200 فقط إذا: الدور ليس superuser ولا BYPASSRLS، وكل جداول المؤسسات FORCE-RLS، والترحيل مطبَّق؛ ويعطي 503 عند انقطاع القاعدة.
- فحص عزل على القاعدة المرحَّلة: مؤسسة ترى صفها فقط، وإدخال عابر مرفوض (42501)، ودور التطبيق لا ينشئ مؤسسات.
- **لم يُجرَّب**: بناء Docker (لا docker في هذه الحاوية)، ولا النشر الفعلي على Railway.

## حدود معروفة (لم تُبنَ أو لم تُختبر بعد)
- لا `locations` (المخزون على مستوى الفرع فقط)، ولا تحويلات بين الفروع (O20)، ولا جلسات صندوق وإغلاقه (O21)، ولا وحدات قياس وتحويلها ولا متغيرات.
- الإرجاع المالي كامل الفاتورة فقط (لا مرتجع جزئي لأسطر).
- لا مهمة تحرير حجوزات منتهية، ولا سياسة مخزون سالب (ممنوع دائماً).
- إعادة المحاولة عند deadlock مبنية لكن لم أُجبر deadlock فعلياً في اختبار.
- المتوسط المرجح يحسب ضمن الدفعات المنتهية أيضاً (تفصيل تكلفة يحتاج قراراً).
- ترقيم الفواتير بقفل صف عداد: بلا فجوات لكنه يسلسل إصدار الفواتير لكل مؤسسة (قد يكون عنق زجاجة عند الحمل العالي).
- لا واجهات (UI) ولا API HTTP ولا مصادقة حقيقية؛ هذه طبقة المجال وقاعدة البيانات فقط.
- كلمات مرور التطوير الافتراضية في `src/db.ts` و`scripts/setup-db.sh` للتطوير المحلي فقط؛ في `APP_ENV=production` غيابها يوقف الإقلاع.
- لم تُجرَّب أحمال كبيرة؛ التزامن اختُبر على اتصالات قليلة.
- فحص حدود الوحدات تم باختبار نصي بسيط وليس بـ dependency-cruiser.
