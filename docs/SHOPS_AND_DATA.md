# المحلات الثلاثة الأولى: الاحتياجات والبيانات والعزل

> الحالة: **مسودة 0.1**. مبنية على معرفة عامة بهذه الأنشطة، **وليست على مقابلات مع أصحابها بعد**.
> كل ما هو مكتوب هنا «افتراض يجب التحقق منه مع المالك» إلى أن يُؤكَّد. أي ذكر لقوانين أو ضرائب أو وثائق مغربية يحتاج مراجعة محاسب/مختص.

المحلات (أسماء توضيحية؛ لا تُنشر أسماء ولا بيانات المحلات الحقيقية في مستودع عام): 1) **محل (أ): جزارة ومشوي ومطعم** (جزارة + مشوي + مطعم) — `shop-a`
2) **محل (ب): ميكانيكا** (ميكانيكا السيارات) — `shop-b`
3) **محل (ج): إنذار وحريق** (بيع وتركيب أجهزة الإنذار والحريق) — `shop-c`

---

## 0. الخلاصة

1. **نواة واحدة + وحدات**. المحلات الثلاثة تتشارك: عملاء، منتجات/قطع، مخزون، فواتير، دفع، موظفون، صلاحيات، تدقيق. وتختلف في وحدات النشاط.
2. **اكتشاف مهم:** الميكانيكي ومحل (ج): إنذار وحريق يتشاركان **وحدة واحدة** هي «الأصول والخدمة»: أصل يخص العميل (سيارة / موقع فيه أجهزة) + أمر عمل + عرض سعر + قطع + يد عاملة + ضمان + تذكير صيانة. نبنيها مرة واحدة تخدم محلين، وتخدم لاحقاً أي محل خدمات (تبريد، كهرباء، سباكة).
3. **أقترح ترتيب المحلات:** المحل (أ) أولاً (النواة جاهزة له فعلاً)، ثم بناء وحدة الأصول والخدمة، ثم المحل (ب)، ثم محل (ج): إنذار وحريق (الأعقد: عقود صيانة دورية وبيانات حساسة).
4. **العزل 6 طبقات** (القسم 5)، والبيانات الأحدّ حساسية (رموز الإنذار، مخططات المواقع) تُشفَّر على مستوى الحقل وتُقيَّد بدور.
5. المحلات الثلاثة **بيانات حقيقية** لأناس حقيقيين: لا نضع أي بيانات حقيقية في بيئة بلا مصادقة ونسخ احتياطي. (القسم 8)

### خريطة الوحدات لكل محل
| الوحدة | المحل (أ) | المحل (ب) | محل (ج): إنذار وحريق |
|---|---|---|---|
| نواة: عملاء، فواتير، دفع، آجل، موظفون، صلاحيات، تدقيق | ✅ | ✅ | ✅ |
| مخزون + مشتريات + موردون | ✅ (دفعات وصلاحية) | ✅ (قطع غيار) | ✅ (أجهزة وملحقات) |
| بيع بالوزن + دفعات + FEFO | ✅ | — | — |
| تحويل/تحضير (إنتاج) + فاقد | ✅ | — | — |
| مطبخ/شواء (KDS) + طاولات + حجز | ✅ | — | — |
| توصيل | ✅ (اختياري) | — | — |
| **الأصول والخدمة** (أصل + أمر عمل + عرض سعر + ضمان) | — | ✅ سيارة | ✅ موقع/جهاز |
| أرقام تسلسلية + ضمان | — | قطع مهمة | ✅ أساسي |
| **عقود صيانة دورية + جدول زيارات** | — | تذكير صيانة | ✅ أساسي |
| فحوصات دورية بقوائم تحقق وتواقيع | — | — | ✅ |
| فنيون + مواعيد + مسارات | — | ✅ (ميكانيكيون ومنصات) | ✅ (فنيون ميدانيون) |
| بيانات حساسة مشفّرة | — | — | ✅ |

## 1. محل (أ): جزارة ومشوي ومطعم (جزارة + مشوي + مطعم)

### 1.1 العمليات اليومية
بيع لحم بالكيلو ← (اختياري) طلب شواء ← تحضير وتقديم ← دفع. مشتريات يومية من المذبح/الموردين. تقطيع وتحويل (لحم ← كفتة/شرائح). وجبات للعائلات بقاعة. طلبات هاتفية/واتساب. توصيل أحياناً. مواسم: رمضان، عيد الأضحى.

### 1.2 البيانات التي نحتاجها منه (قائمة جمع)
- **المنتجات**: كل أنواع اللحوم والمنتجات (بقر، غنم، دجاج، كفتة، سجق…) مع الوحدة والسعر الحالي.
- **قائمة المشوي والأطباق** والأسعار، وما تحتويه (الوصفة: كم لحم/خبز/سلطة).
- **الموردون**: أسماؤهم، هواتفهم، شروط الدفع (نقداً/آجل)، وكيف يُسلَّم اللحم (ذبيحة كاملة؟ قطع؟).
- **نسب الفاقد المعتادة** لكل قطعة (تقدير المالك، ثم نقيسها فعلياً).
- **الميزان**: ماركته وطريقة الربط.
- **الموظفون وأدوارهم**: جزارون، شوّاؤون، كاشير، نُدُل، سائق.
- **الطاولات** وعددها، وأقسام القاعة (عائلات).
- **مناطق التوصيل** والرسوم.
- **أجواء الضريبة**: نسب TVA المطبقة على كل صنف (تُحدد مع المحاسب).
- **معلومات الشركة**: الاسم القانوني، ICE، IF، RC، الشعار، العنوان، الهاتف (للفاتورة).
- **أرقام اليوم**: متوسط المبيعات اليومية، أيام الذروة، هامش الربح الذي يظنه.

### 1.3 الميزات
**أساسية (النموذج الأولي يغطي جزءاً منها):**
| الميزة | الحالة |
|---|---|
| بيع بالوزن، الوزن الفعلي، دفعات، FEFO | ✅ مبني |
| تحويل ← كفتة، الفاقد، التكلفة | ✅ مبني |
| شواء كخدمة + وجبة backflush | ✅ مبني |
| إلغاء/مرتجع/تلف موثق | ✅ مبني |
| آجل ودفعات جزئية (مطاعم تشتري منه) | ✅ مبني |
| **شاشة المطبخ/الشواء (KDS)** | ❌ UI |
| **POS لمس بأزرار كبيرة** | ❌ UI |
| **ربط الميزان** | ❌ (إدخال يدوي أولاً) |
| **جلسة صندوق وإغلاقه** | ❌ |
| **طاولات وحجز عائلات** | ❌ |
| طباعة تذكرة/فاتورة (بالعربية والفرنسية) | ❌ |

**لاحقاً:** توصيل وتتبع، PWA للطلب، حجز الأضحية (موسمي)، اشتراك أسبوعي، تتبع QR للدفعة، مراقبة حرارة الثلاجة، تنبؤ الطلب.

### 1.4 ما يحتاجه مدير المحل
- **اليوم**: المبيعات بالدرهم والكيلو، عدد الطلبات، المتوسط، حسب القسم (جزارة/مشوي/مطعم)، وحسب الدفع (نقد/بطاقة/آجل).
- **المخزون**: كل قطعة بالكيلو، المحجوز، المتاح، الدفعات القريبة الانتهاء، ما نقص عن الحد.
- **الربح**: هامش المواد لكل منتج، الفاقد الفعلي مقابل المتوقع (انحراف)، تكلفة التحويل، مع **مؤشر اكتمال البيانات**.
- **الرقابة**: فروق الصندوق، الإلغاءات والتلف (من/متى/كم)، الخصومات والموافقات، الموظفون.
- **الديون**: من عليه مال، منذ متى.
- **الموردون**: ما اشتريته وبكم، تغير الأسعار، ديون الموردين.
- **التنبيهات**: مخزون ناقص، دفعة تنتهي، فرق صندوق، إلغاء مشبوه.

### 1.5 أدواره
مالك، مدير، كاشير، جزار، شواء، نادل، سائق، (مسؤول مخزون). الصلاحيات الحساسة: خصم، إلغاء بعد الوزن، تصحيح مخزون، إغلاق صندوق.

### 1.6 أسئلة لمالك المحل (أ)
هل يشتري ذبائح كاملة أم قطعاً؟ كيف يقيس الفاقد اليوم؟ هل يبيع بالآجل؟ لمن؟ هل الشواء يُباع بالكيلو أم بالطبق؟ هل يوجد أكثر من فرع؟ كم موظفاً؟ ما الذي يُضيّعه اليوم من مال أو وقت؟

## 2. محل (ب): ميكانيكا (ميكانيكا السيارات)

### 2.1 العمليات اليومية
سيارة تدخل ← استقبال وتشخيص ← **عرض سعر (devis)** ← موافقة العميل ← **أمر إصلاح (OR / ordre de réparation)** ← قطع (من مخزونه أو يطلبها من مورد) + ساعات عمل ← تسليم ← فاتورة ← تذكير بالصيانة القادمة. يتعامل مع زبائن دائمين ومع تجار/ورشات أخرى أحياناً.

### 2.2 البيانات
**الزبون**: الاسم، الهاتف (واتساب)، العنوان، نوع (فرد/شركة)، ICE إن شركة، رصيد آجل.
**السيارة (أصل)**: رقم التسجيل (matricule)، الماركة، الطراز، السنة، الوقود، **رقم الهيكل VIN**، عداد الكيلومترات عند كل زيارة، اللون، ملاحظات حالة (خدوش/أضرار عند الاستلام) + صور.
**أمر الإصلاح**: التاريخ، الزبون، السيارة، الكيلومتراج، **شكوى الزبون**، التشخيص، الأعمال المطلوبة (أسطر)، القطع المستعملة، ساعات العمل (ميكانيكي × ساعات × سعر الساعة)، الحالة (مفتوح ← بانتظار موافقة ← بانتظار قطعة ← قيد العمل ← جاهز ← سُلِّم)، المنصة/الرافعة (bay)، الصور قبل/بعد، **ضمان الإصلاح** (مدة/كم).
**القطع**: المرجع، العلامة (OEM/aftermarket)، سعر الشراء، سعر البيع، المورد، مخزون، سيارات متوافقة.
**الأعمال القياسية (forfaits)**: «تغيير زيت+فلتر» بسعر ثابت وقطع محددة.
**الفنيون**: الاسم، الأجر، التخصص، ساعات كل أمر.
**الموردون**: أسماؤهم، طلبات القطع، أسعار.
**التذكير**: تاريخ/كم الصيانة القادمة (زيت، فرامل، فحص تقني).

### 2.3 الميزات
**أساسية:** ملف زبون + سيارة، سجل صيانة كامل لكل سيارة، عرض سعر ← أمر إصلاح ← فاتورة، قطع من المخزون أو طلب خارجي، يد عاملة بالساعة أو سعر ثابت، حالة العمل، صور، دفع جزئي/آجل، ضمان.
**ذات قيمة عالية:** **تذكيرات واتساب/SMS** للصيانة الدورية (تجلب زبائن عائدين)، موافقة الزبون على عرض السعر برابط، طباعة أمر وفاتورة.
**لاحقاً:** جدول منصات (bays)، ربح الفني، طلب قطع آلي من المورد، تحليل ربحية القطع مقابل اليد العاملة، فحص تقني.

### 2.4 ما يحتاجه المدير
- **السيارات اليوم**: ما في الورشة، حالة كل واحدة، منذ متى، ماذا تنتظر (موافقة/قطعة).
- **المال**: إيراد القطع واليد العاملة، الهامش، الفواتير غير المدفوعة، الديون.
- **الإنتاجية**: ساعات كل ميكانيكي مقابل المفوترة، أمور متأخرة.
- **المخزون**: قطع راكدة، قطع مطلوبة كثيراً، ما يجب طلبه.
- **الزبائن**: من لم يزر منذ مدة (للتذكير)، أفضل الزبائن.
- **الجودة**: إعادة إصلاح خلال الضمان (مؤشر مهم).

### 2.5 أدواره
مالك، استقبال/مدير، ميكانيكي (يرى أوامره وساعاته فقط)، أمين مخزون قطع، محاسب.

### 2.6 أسئلة لعبد الحميد
هل يبيع القطع أم يُركّبها فقط؟ هل يحتفظ بمخزون؟ كيف يسجل اليوم (دفتر؟ واتساب؟) وكم زبوناً شهرياً؟ هل يقدم عروض أسعار مكتوبة؟ كم ميكانيكياً؟ كيف يدفعون له؟ هل يريد تذكيراً للزبائن؟

## 3. محل (ج): إنذار وحريق (إنذار وحريق: بيع وتركيب وصيانة)

### 3.1 العمليات اليومية
طلب عميل ← **زيارة معاينة** للموقع ← **عرض سعر** (معدات + تركيب) ← قبول ← **تركيب** ← تسليم + شهادة/محضر ← **عقد صيانة دورية** (زيارات وفحوصات) ← تدخل عند عطل. أطفاة الحريق تتطلب **فحصاً دورياً وإعادة تعبئة**. إيراد متكرر من عقود الصيانة.

### 3.2 البيانات
**العميل**: فرد/شركة/مبنى، ICE، جهات اتصال (مسؤول الموقع، حارس)، فاتورة وعقود.
**الموقع (site)**: عنوان، نوع (مبنى/مصنع/محل)، **مخطط الموقع**، جهة اتصال طوارئ، ساعات الدخول، ملاحظات وصول. **عميل واحد عدة مواقع.**
**الأجهزة المركبة (أصول)**: النوع (لوحة إنذار، كاشف دخان/حرارة، صفارة، كاميرا، **مطفأة**، خرطوم، لوحة تحكم)، الماركة، الموديل، **الرقم التسلسلي**، تاريخ التركيب، **الضمان**، المكان بالضبط في الموقع، حالة، تاريخ آخر فحص، تاريخ **الفحص/الصلاحية القادمة**.
**عرض السعر**: أسطر (معدات/تركيب/كابلات/أجرة)، خصم، صلاحية، نسخ، قبول بتوقيع.
**أمر التركيب/التدخل**: الفنيون، التاريخ والوقت، قائمة تحقق، قطع مستعملة، **صور**، **توقيع العميل** على محضر التسليم، ملاحظات.
**عقد الصيانة**: العميل والموقع، المدة، الدورية (شهرية/فصلية/سنوية)، الأجهزة المشمولة، السعر، شروط الاستجابة (SLA)، **جدول زيارات تلقائي**.
**الفحوصات الدورية**: قائمة تحقق لكل نوع جهاز، النتائج (سليم/معطوب/مستبدل)، **محضر موقّع**، توصيات.
**الفني**: الاسم، المهارات/الشهادات، المسار اليومي.
**البيانات الحساسة جداً (⚠️ تُشفَّر وتُقيَّد):** **رموز الإنذار وكلمات مرور اللوحات**، مخططات المبنى، أماكن الكاميرات، أوقات غياب أصحاب الموقع. إن تسربت قد تسهّل جريمة.

### 3.3 الميزات
**أساسية:** عملاء ومواقع متعددة، سجل أجهزة بأرقام تسلسلية وضمان، عرض سعر ← أمر تركيب ← فاتورة، **عقود صيانة وجدولة زيارات تلقائية وتذكيرات**، محضر تدخل موقّع بصور، تتبع صلاحية المطافئ والفحص، مخزون معدات (أرقام تسلسلية).
**قيمة عالية:** **لوحة «ما ينتهي هذا الشهر»** (فحوصات، عقود، ضمانات) لأنها **إيراد مضمون**، تذكير العميل، شهادة فحص تُطبع، ضمان لكل جهاز، تطبيق فني للهاتف (بدون إنترنت أحياناً في المواقع).
**لاحقاً:** مسار الفنيين على الخريطة، ربط مراقبة عن بعد، تقارير امتثال لكل موقع، بوابة عميل.

### 3.4 ما يحتاجه المدير
- **المتجدد**: عقود تنتهي قريباً، زيارات متأخرة، مطافئ تحتاج فحصاً، ضمانات تنتهي.
- **المال**: إيراد التركيب مقابل الصيانة (الأخير متكرر)، عروض أسعار معلقة (لم يُجَب عليها)، فواتير غير مدفوعة، ربحية كل عقد.
- **الفنيون**: زياراتهم اليوم، المتأخر، ساعات كل أمر.
- **المخزون**: معدات متوفرة، ناقصة، مرتبطة بعقود قادمة.
- **المخاطر**: مواقع بلا فحص منذ مدة (مسؤولية قانونية!)، أجهزة معطوبة لم تُصلح.

### 3.5 أدواره
مالك، مدير مبيعات (عروض)، منسق (جدولة)، فني (أوامره ومواقعه فقط، **بلا رؤية الأسعار**)، أمين مخزون، محاسب. **وصول الرموز الحساسة: المالك ومن يفوَّض فقط، وكل وصول مسجّل.**

### 3.6 أسئلة لـ محل (ج): إنذار وحريق
ما نسبة الإيراد من التركيب مقابل الصيانة؟ كم عقد صيانة نشط؟ كيف تُتابع الفحوصات اليوم؟ هل هناك شهادات/معايير ملزمة لعملائكم (وما هي)؟ هل يُشغّل الفنيون في مواقع بلا إنترنت؟ هل تحفظون رموز الإنذار الآن، وأين؟

## 4. ما يحتاجه «مدير المنصة» (أنت)

- **المؤسسات**: قائمة المحلات، حالتها، باقتها، تاريخ الاشتراك، آخر نشاط، حدود الاستخدام (مستخدمون/منتجات/حجم).
- **التهيئة**: إنشاء محل من قالب، تفعيل/تعطيل الوحدات، الهوية (اسم، شعار، ألوان، دومين).
- **الصحة التقنية**: أخطاء، بطء، فشل نسخ احتياطي، حجم قاعدة البيانات لكل محل.
- **الدعم**: الدخول كمحل (بتفويض مؤقت ومسجّل)، تذاكر، سجل تغييرات.
- **المالية**: الاشتراكات، المتأخر، الإيراد.
- **الامتثال**: من وافق على ماذا، طلبات تصدير/حذف البيانات.
- **لا يرى** بيانات تشغيل المحلات (عملاؤها، مبيعاتها) إلا بتفويض. هو يدير المنصة لا الأعمال.

| 1 | **قاعدة البيانات** | `tenant_id` في كل جدول، RLS مع FORCE، دور تطبيق بلا BYPASSRLS ولا ملكية، مفاتيح أجنبية مركّبة تمنع الإشارة عبر المؤسسات | ✅ مبني ومختبر (T9–T11) |
| 2 | **التطبيق/API** | كل طلب يحمل المؤسسة من الجلسة (لا من جسم الطلب)، `SET LOCAL app.tenant_id` في كل معاملة، رفض الطلب بلا سياق | جزئي: السياق مبني، لا API بعد |
| 3 | **الملفات والصور** | مسار `tenants/{id}/…`، روابط موقّعة قصيرة العمر، تحقق عضوية قبل التوقيع، لا روابط عامة | ❌ |
| 4 | **الأسرار والبيانات الحساسة** | تشفير على مستوى الحقل لرموز الإنذار والمخططات (مفتاح مشتق لكل مؤسسة)، عرض مقنّع، كل كشف مسجّل | ❌ (يلزم قبل محل (ج): إنذار وحريق) |
| 5 | **التشغيل** | نسخ احتياطي مع **اختبار استعادة**، تصدير/حذف بيانات مؤسسة واحدة، سجلات بلا بيانات شخصية، حدود معدل لكل مؤسسة | ❌ |
| 6 | **البشر** | دعم فني بتفويض مؤقت وسجل، موافقات، فصل المهام، لا حسابات مشتركة | جزئي |

### تقسيم البيانات
- **عالمي** (بلا tenant): الباقات، القوالب، كتالوج الصلاحيات، هويات المستخدمين.
- **مؤسسة**: كل شيء آخر.
- **فرع**: مخزون، صندوق، طلبات؛ نطاق المستخدم (`branch_ids`) يحدد ما يراه.
- **حساس**: مصنَّف لاحقاً (جدول التصنيف أدناه).

| التصنيف | أمثلة | المعالجة |
|---|---|---|
| عام | اسم المحل، شعاره، قائمة الأسعار المعروضة | عادي |
| داخلي | مبيعات، مخزون، موردون | RLS + أدوار |
| سري | أرباح، ديون، رواتب، هواتف الزبناء | أدوار محددة + تدقيق عند التصدير |
| **حساس جداً** | رموز إنذار، مخططات مواقع، أماكن كاميرات | تشفير حقل + دور خاص + تسجيل كل كشف + لا تصدير |

### ما لن نفعله
- لا تقارير تجمع بيانات مؤسستين، حتى مجهولة، دون موافقة صريحة منهم.
- لا قاعدة بيانات منسوخة بين المحلات للتجارب. بيانات الاختبار اصطناعية.
- لا بيانات حقيقية في بيئة الاختبار.

### متى نعزل بقاعدة مستقلة؟
عميل كبير، أو متطلب تعاقدي، أو حجم يؤثر على الآخرين. الباقي بقاعدة مشتركة ما دام RLS مختبراً.

## 6. الفجوات بين النموذج الأولي والمحلات الثلاثة

| ما ينقص | يخدم | الأولوية |
|---|---|---|
| **API HTTP + مصادقة (جلسات/JWT) + ربط المستخدم بالمؤسسة** | الكل | 1 |
| **POS + KDS (واجهات)** | المحل (أ) | 1 |
| جلسة الصندوق وإغلاقه، طباعة | المحل (أ) (ثم الكل) | 1 |
| **وحدة الأصول والخدمة** (assets, quotes, service_orders, labor, warranty, work photos) | المحل (ب) +المحل (ج) | 2 |
| **عقود الصيانة وجدولة الزيارات والتذكيرات** |المحل (ج) (والمحل (ب) للتذكير) | 2 |
| تشفير حقل البيانات الحساسة |المحل (ج) | 2 (قبل بيانات pp) |
| تذكيرات واتساب/SMS | المحل (ب) +المحل (ج) | 3 |
| تطبيق فني (موبايل، ربما بدون إنترنت) |المحل (ج) | 3 |
| رفع الصور وملفات (تخزين معزول) | المحل (ب) +المحل (ج) | 2 |
| تحويل بين فروع، وحدات قياس | حسب الحاجة | 3 |
| مراقبة الأخطاء والنسخ الاحتياطي واختبار الاستعادة | الكل | 1 |
| قوالب المحلات (seed جاهز لكل نشاط) | الكل | 2 |

### خطة مقترحة
- **المرحلة أ (الأساس):** API + مصادقة + نسخ احتياطي + بيئة staging. *(لازم قبل أي بيانات حقيقية)*
- **المرحلة ب (المحل (أ)):** POS/KDS/صندوق + قالب جزارة + تجربة ميدانية قصيرة.
- **المرحلة ج (الأصول والخدمة):** نبنيها على المحل (ب) لأنها أبسط (سيارة + أمر إصلاح).
- **المرحلة د (محل (ج): إنذار وحريق):** عقود وفحوصات وتشفير حقول + تطبيق فني.
كل مرحلة **معيار قبول ميداني**: هل استعمله الموظف بلا مساعدة؟ هل طابقت الأرقام الواقع؟

## 7. قائمة المعلومات التي أحتاجها منك الآن (لكل محل)
1. اسم المالك ونمط نشاطه اليوم (كيف يسجل: دفتر/واتساب/برنامج).
2. 20–50 منتجاً/خدمة وأسعارها (يكفي لبدء تجربة).
3. موظفوه وأدوارهم.
4. بيانات الفاتورة (اسم قانوني، ICE، IF، RC، عنوان، شعار).
5. **أكبر ثلاث مشاكل يومية** عنده (هذا يحدد ما نبنيه أولاً).
6. هل يوافق على تجربة 2–4 أسابيع بلا التزام؟ وبأي جهاز (هاتف/تابلت/حاسوب)؟
7. **موافقته الكتابية** على معالجة بيانات عملائه (متطلب CNDP، يُراجع مع مختص).

## 8. قواعد التعامل مع بيانات المحلات الحقيقية
- لا بيانات حقيقية قبل: مصادقة، نسخ احتياطي واستعادة مجربة، HTTPS، تشفير الحقول الحساسة (لـ pp).
- بيئتان: **staging** (بيانات اصطناعية) و**production** (حقيقية، بعد موافقتك).
- استضافة قاعدة البيانات داخل/خارج المغرب: قرار يُحسم مع مختص امتثال قبل الإنتاج.
- نسخة احتياطية يومية + **اختبار استعادة شهري**.
- كل محل يستطيع **تصدير بياناته كاملة** وحذفها.
